## App 电脑端配套插件

`companion/` 的单元检查覆盖配对响应晚到、页面关闭和卸载清理、二维码过期、显式批准、二次确认撤销、同源所有者通道、缺 Bridge 提示，以及慢于轮询间隔的状态请求。状态请求使用 single-flight；操作完成后重新获取状态，旧请求不能覆盖新操作的结果。

0.1.1 增加公开 `settings.section` 的“移动设备”入口，同时保留 bundle 配置页。每次挂载创建独立 controller；两个页面同时存在时，关闭其中一个不会中止另一页的请求或清除另一页的二维码。插件卸载仍会统一释放所有尚在使用的 controller。两个入口使用相同的 owner carrier，权限范围不变。

打包生命周期检查独立于浏览器交互验收，使用公开 DSH `0.2.1-rc.2`、已审查 DS Bot fixture 和 mock 模型。它验证官方管理器安装精确 `.tgz`、App 插件独立启停和移除、缺 Bridge 时的设置状态，以及 Bridge 服务器身份和设备授权保留。包管理器要求宿主重启时，测试在受控重启后核对最终状态；不会把网络请求中断当作插件安装成功。

实际浏览器交互已在隔离宿主中验证配对二维码与手动 JSON、手机 SDK 请求、电脑批准、会话读取、二次确认撤销及撤销后旧 access token 被拒绝。此处的“手机”是合成 SDK 测试设备，不能代替 iOS / Android 真机扫码、相机权限和安全存储验收。

## 0.1.4 消息与滚动回归

实际 `useConversation` hook 与 SDK 连接隔离 HTTP/WebSocket 服务器，共 14 项检查。点击发送后，在 SQLite、凭据或目标查询尚未完成的同一次渲染中，气泡显示“正在发送”、输入框清空、附件归入该气泡；未确认期间可编辑下一条草稿，单个未决请求完成前不重复发送。HTTP 尚未返回时不显示 Sent，canonical 消息与 HTTP 确认先后到达均只保留一条。新请求持久化后直接 POST；恢复或不确定的请求始终先查原回执，404 才提交相同载荷。

检查还覆盖目标/存储失败时不提前 POST、同文字的新草稿不被清空、unknown/rejected 原文与附件保留、恢复 intent 不自动发送，以及切换主机、会话或重新挂载后的迟到回执。多个 hook 实例共享同一模块的持久化队列，旧的首次清框不能覆盖新实例编辑的草稿；SQLite 条件更新仅匹配当前 requestId，旧失败不能覆盖新 outbox。Node.js 内置 SQLite 直接执行实际缓存源码，另行检查竞争占槽、条件清理和清历史保留未决发送及新草稿。这些是隔离 fixture 与 SQLite 检查，不是生产真实发送验收；未向用户的主机发送模型测试消息。

前台连接保留池按 client、主机和会话隔离，最多保留三个空闲会话，30 秒后释放；App 后台或切换主机立即清理。独立 fixture 覆盖慢 REST 或 SQLite 水合不阻塞 WS ready、同一会话短期返回只握手一次、A/B/A 两个握手、后台释放、失效状态、合并快照，以及真实 reconnecting 状态的回放。该测试范围不扩展为生产连接次数的抓包证明。

最终 Node.js `24.13.0` 的 `npm run check` 通过 App 148 项、SDK 30 项、Bridge 30 项及 companion 18 项，并通过 TypeScript、Bridge lint 和 companion build。源码审计与 `git diff --check` 通过；签名资料、设备标识、配对信息及真实聊天截图未进入公开仓库。

滚动控制器使用长历史事件轨迹，覆盖底部 ±0.5 / ±1 / ±40 / ±400 的反复内容估算、阅读历史、拖动和惯性结束、实际新消息与流式内容、键盘 viewport、回到底部按钮和跳转途中高度修订。相同 tail 的 content 测量不能自行续期滚动修正。1000 条长消息重复快照保留数组与行引用；Node 性能检查不等同 Hermes 真机性能结果。

早期 build `3` 曾通过 30.4 秒静置采样，但随后在真实手势中发现过约 `5862.6 pt` 的跳跃。该静置结果不足以证明交互稳定。最终使用反转列表、固定原生锚定配置与有界跟随，并以明确进入和连续手势分别验收；不会将早期静置记录替代最终交互证据。
