# 0.1.4-preview.1

Native App `0.1.4` fixes chat message visibility and bottom-of-history scrolling. Desktop companion remains `0.2.0`; Mobile Bridge remains `0.0.6`.

## Changes

- Tapping Send immediately shows a local user bubble, clears the composer and moves its attachments into the bubble before storage, credentials or target lookup complete. The bubble says “Sending…” until the host confirms it. You can write the next draft while the single unresolved send is checked; acceptance never clears that newer text.
- The visible conversation uses bounded HTTP synchronization while its WebSocket reconnects. Reads pause in the background or when navigating away, do not overlap, and back off after failures. Unknown and rejected sends retain their original text, attachments and request identity in a durable outbox. Checking their status reconciles the original receipt before another POST; a brand-new durable send skips the preliminary receipt lookup.
- Returning to a recent conversation reuses its foreground stream for up to 30 seconds, with at most three idle conversations retained. History and WebSocket startup run in parallel; cached messages never imply an online connection. Backgrounding or changing hosts releases the retained streams.
- Content-height estimates can no longer repeatedly trigger scrolling to the bottom. Layout corrections have a bounded budget and the native history-anchor configuration remains constant for the lifetime of the list, including overscroll gestures. A drag ending at the bottom does not itself force another scroll.
- Conversations render from the newest end using an inverted native list and reverse chronological data. Native offset zero shows the latest message directly; opening does not use delayed retries that visibly scroll through old history. Explicitly selecting a conversation opens at the latest message, while returning from its details preserves the reading position.
- Identical history snapshots retain their existing message and array references. Reconnection status remains visible above the composer.
- Scrolling away from the latest message reveals a small round down-arrow button above the composer. It follows the selected light/dark theme, works without unread messages, and disappears when the bottom is reached.
- Late send responses are bound to their original host and conversation. SQLite conditional updates protect a newer send from an older mounted screen; shared draft-write ordering prevents an old clear from erasing a newly edited draft. Clearing history preserves unresolved sends and their next drafts.
- Both README versions show the complete desktop phone-access panel at a readable size.

## Validation

Validation includes deterministic scroll traces for long histories, alternating content-height estimates, keyboard resizing, dragging and streaming, plus the actual conversation hook and SDK against an isolated HTTP/WebSocket fixture. The fixture covers WebSocket rejection, accepted/rejected/unknown receipts, later Bot output, duplicate events, backgrounding and navigation during a pending submission, gates on SQLite/credentials/target/HTTP, identical next drafts, restored outboxes, and late responses across mounted hook instances. Actual SQLite tests cover competing send ownership and history clearing. It does not send test prompts to a user's live profile.

This remains a source preview. Public signed IPA/APK files are not provided. Device installation evidence and reproducible checks are recorded in [validation](../validation.md).
