# 0.1.4-preview.1

Native App `0.1.4` fixes chat message visibility and bottom-of-history scrolling. Desktop companion remains `0.2.0`; Mobile Bridge remains `0.0.6`.

## Changes

- An accepted HTTP submission appears immediately in the conversation and local cache, even while the real-time connection is unavailable. The canonical transcript replaces the local receipt by session and request identity without duplicate bubbles.
- The visible conversation uses bounded HTTP synchronization while its WebSocket reconnects. Reads pause in the background or when navigating away, do not overlap, and back off after failures. Unknown and rejected sends keep their original draft and request identity.
- Content-height estimates can no longer repeatedly trigger scrolling to the bottom. Layout corrections have a bounded budget; historical reading retains its native anchor, while following the latest message uses one scrolling mechanism. A drag ending at the bottom does not itself force another scroll.
- Identical history snapshots retain their existing message and array references. Reconnection status remains visible above the composer.
- Late send responses are bound to their original host and conversation and cannot insert messages into another chat or erase its draft.
- Both README versions show the complete desktop phone-access panel at a readable size.

## Validation

Validation includes deterministic scroll traces for long histories, alternating content-height estimates, keyboard resizing, dragging and streaming, plus the actual conversation hook and SDK against an isolated HTTP/WebSocket fixture. The fixture covers WebSocket rejection, accepted/rejected/unknown receipts, later Bot output, duplicate events, backgrounding and navigation during a pending submission. It does not send test prompts to a user's live profile.

This remains a source preview. Public signed IPA/APK files are not provided. Device installation evidence and reproducible checks are recorded in [validation](../validation.md).
