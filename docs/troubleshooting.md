# 故障排查

先确认当前使用的是原生 App；浏览器问题请看 [Mobile Web 排错](https://github.com/MuQY1818/ds-bot-mobile-web/blob/main/docs/troubleshooting.md)。

## 电脑提示等待 Bridge 或连接服务未就绪

检查是否在日常使用的 DSH 环境安装并启用了 `ds-bot-mobile-bridge`，并已设置 `enabled`、专用 `home`、监听和 HTTPS。配置见[Bridge 指南](bridge.md)。App 配套插件只是管理界面，不会替你创建传输服务。

## 找不到配对页

确认 `ds-bot-mobile-app` 配套插件已启用，从电脑账户菜单打开 **手机访问 → App**。菜单不可见时，从官方插件管理器的本包配置页打开。第三方市场显示包列表不代表没有其他入口。

## 扫码失败或一直等待批准

确认使用的是 App 标签的配对码，而非 Web 登录码。重新生成未过期的码，核对手机可达 HTTPS，随后在电脑批准匹配的设备请求。只扫码不会自动授权。

## 手机显示离线或反复连接

保持电脑唤醒、DSH 和 Bridge 运行。使用私网时检查两端连接；网络入口变化后检查主机身份与证书。不要首先删除 App、清空本地存储或更换 Bridge home，这可能使配对失效。

## 发送状态一直未知

先使用原请求的状态检查，不要反复发送同一内容。主机可能已经接受消息，但确认尚未到达。原内容会保留；明确拒绝后再按界面处理草稿。

## 更新后需要重新配对

检查是否保留同一应用标识和签名身份，以及 Bridge 的原状态目录。覆盖更新应保留数据；重新安装或更换状态目录可能生成新的设备身份。

## 页面出现演示数据

开发设计预览使用示例会话，不连接真实主机。实际使用需原生客户端连接已配置的 Bridge。不要把 Web 预览当作已完成的真实设备连接。

## 提交问题

在 [Issues](https://github.com/MuQY1818/ds-bot-mobile-app/issues) 说明平台、App 与电脑插件版本、错误文字和复现步骤。遮住配对二维码、主机地址、设备身份与私人聊天。
